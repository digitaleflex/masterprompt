# 6. Tests de Résilience & Chaos Engineering (Prompts 86-100)

*Focus : Fiabilité sous pression.*

## Prompt 86
Propose un scénario de 'Chaos Engineering' pour tester comment l'application réagit si la base de données devient inaccessible.

## Prompt 87
Simule une attaque DoS sur ce service : à quel point le système d'auto-scaling réagit-il ?

## Prompt 88
Vérifie la robustesse de la gestion d'erreurs : l'application plante-t-elle si un service tiers renvoie un JSON malformé ?

## Prompt 89
Comment tester la procédure de Disaster Recovery (reprise après sinistre) de manière automatisée ?

## Prompt 90
Génère un test de charge pour identifier le point de rupture des connexions simultanées à l'API.

## Prompt 91
Analyse la tolérance aux pannes : comment le système réagit-il à la perte d'un nœud ?

## Prompt 92
Comment tester le mécanisme de basculement (failover) entre les environnements de production ?

## Prompt 93
Vérifie la robustesse face à des latences réseau élevées ou des coupures temporaires.

## Prompt 94
Comment simuler la perte de données pour tester les processus de restauration ?

## Prompt 95
Analyse la résilience face à des attaques par déni de service (DoS/DDoS).

## Prompt 96
Comment tester la récupération après une attaque de cryptomalware ou ransomware ?

## Prompt 97
Vérifie la capacité de l'application à gérer des volumes de données anormalement élevés.

## Prompt 98
Comment simuler la perte d'un service tiers critique (ex: authentification, paiement) ?

## Prompt 99
Analyse la capacité de l'application à fonctionner en mode dégradé sans perdre de données critiques.

## Prompt 100
Comment implémenter des tests de résilience automatiques dans le pipeline CI/CD ?
